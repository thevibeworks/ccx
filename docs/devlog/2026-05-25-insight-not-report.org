* [2026-05-25] Insight, Not Report                            :ARCH:WIP:

** Tension

After PR #16 merged, the next design question was whether the deterministic
HTML surface should become a separate command, something like =ccx report=.

That suggestion came from a real concern: the =/ccx-insight= skill spec is
heavy, and asking an agent to build a complete HTML artifact from scratch is
execution risk. A scaffold generated by Go could lower that risk by owning
structure, accessibility, print styles, evidence tables, and data-quality
panels while leaving interpretation to the skill.

But the proposed noun was wrong.

=report= describes the container. =insight= describes the user value. The
human is not asking for a "report"; the human is asking to understand what
happened, what matters, what is proven, and what to do next. HTML is just one
artifact for insight.

The mistake was not random. It came from overcorrecting against the previous
failure. The old =ccx insight= implementation had impersonated judgment, so
the next thought was to protect the evidence boundary by avoiding the word
=insight= in the CLI. That was backwards. The boundary is real, but it should
be enforced by schema, labels, empty unreviewed sections, and claim status.
It should not leak into the product noun as a generic artifact word.

This is a taste failure: optimizing the name for internal anxiety instead of
the user's mental model.

** Observation

The merged product vocabulary is already coherent:

| Command / Skill | Role |
|-----------------+------|
| =ccx sessions= | list containers |
| =ccx log= | time-sliced evidence bundle |
| =ccx trace= | single-session evidence bundle |
| =/ccx-insight= | interpret evidence into human review |
| =/ccx-context-fold= | fold a trace into durable decisions and knowledge |

Introducing =ccx report= would create a new top-level product noun for an
output artifact. That dilutes the direction exactly when the vocabulary has
started to become precise.

The better correction is to keep =insight= as the product surface and make
HTML an output mode or artifact:

#+begin_src sh
ccx insight --scope yesterday --tz +8 --html
ccx insight --since 2026-05-21 --until 2026-05-22 --tz +8 --html
ccx insight --input bundle.json --html
#+end_src

This does not mean reviving the old fake-judgment =ccx insight=. The old
mistake was not the word "insight." The mistake was letting a deterministic
CLI impersonate interpretation.

The reasoning bug was a category error:

| Concern | Wrong response | Better response |
|---------+----------------+-----------------|
| CLI must not fake judgment | Rename artifact surface to =report= | Keep =insight=; label unreviewed sections and cite evidence |
| Agent spec is heavy | Add a generic command noun | Add deterministic insight scaffolding if execution fails |
| HTML is only an output | Make the output the product name | Treat HTML as an artifact of insight |
| Previous =ccx insight= was wrong | Avoid the noun | Reclaim the noun with a stricter contract |

The user correction exposed this immediately:

#+begin_quote
html report is just an artifact for the insight, it's not a big deal
#+end_quote

** Decision

Keep the user-facing noun as =insight=.

The boundary should live inside the implementation and docs, not in a generic
top-level command name:

| Layer | Responsibility |
|-------+----------------|
| =ccx log= | evidence records, source files, scope relation, metrics |
| =ccx insight= CLI surface | deterministic insight shell: scope, metrics, data quality, evidence refs, empty review sections |
| =/ccx-insight= skill | interpretation: claims, workstreams, decisions, confidence, next moves |
| HTML artifact | one rendering of insight, not the product itself |

The road not taken: =ccx report=. It sounds safer architecturally, but it is
a defensive name. It encodes fear of overclaiming into the product noun. That
fear is valid, but it should be handled by claim ledgers, evidence refs,
unreviewed labels, and empty deterministic sections rather than by making the
command generic.

The rejected idea is not only weaker; it points future contributors in the
wrong direction. =report= invites a taxonomy of artifacts. =insight= invites a
product question: what does the human need to understand, and what evidence
supports it?

If a scaffold is built, it should be framed as insight scaffolding:

#+begin_src sh
ccx insight --input /tmp/ccx-log.json --html --output /tmp/insight.html
#+end_src

or, if the team wants an explicit non-judgment mode:

#+begin_src sh
ccx insight --input /tmp/ccx-log.json --html --scaffold
#+end_src

In scaffold mode, the CLI may render deterministic structure and provenance.
It must leave interpretive sections visibly unreviewed unless the skill fills
them.

** Tradeoff

Keeping =insight= increases the burden on the implementation to avoid the old
mistake. The word is valuable but dangerous: it invites the CLI to sound
smarter than it is.

That burden is acceptable because the product already has the right guardrails:

- =ccx.log.v1= is evidence, not narrative.
- =metrics.sessions= must be labeled as source log files unless a separate
  logical-session model exists.
- completion requires observed or human-stated evidence, not assistant prose.
- unverified and contradicted claims are first-class statuses.
- the skill owns interpretation and must show its work.

The cost of =report= would be worse. It would make the product easier to
explain internally but weaker to users. "Report" is any file with sections.
"Insight" is the thing the user came for.

** Next

The next branch should prove insight executability, not invent another noun.

The smallest useful next move:

1. Add a golden-file fixture for =ccx log= so the evidence bundle contract is
   locked mechanically.
2. Define =/ccx-insight= failure modes: zero records, truncation, massive
   bundles, stale evidence refs, duplicate-looking Codex records, and missing
   writable output path.
3. Build one deterministic =ccx insight --html --scaffold= prototype only if
   the skill fails to produce the full artifact reliably from the current spec.

The live wire is not "more intelligence." It is reliable choreography between
deterministic structure and agent judgment.
