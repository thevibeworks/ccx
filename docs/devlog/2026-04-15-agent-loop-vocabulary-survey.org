* [2026-04-15] Dev Log: Agent-Loop Vocabulary Survey             :ARCH:REFERENCE:

** Context

Systematic survey of the full agent-loop vocabularies emitted by Claude Code
(v2.1.88 source + v2.1.109 bundle) and OpenAI Codex (Rust protocol crate,
v2 rollout format). Goal: enumerate every element =ccx='s session viewer must
render, identify coverage gaps, and seed a real-tools test fixture that locks
the surface down so future tool additions are caught mechanically rather than
via user reports.

Codebase: =github.com/thevibeworks/ccx=, branch =v0.next-plus-1= (PR #8).
Reference sources consumed:
- =reference/claude-code-2188/src/= — decompiled TypeScript, full readability
- =/tmp/cc-2.1.109/package/cli.js= — minified bundle; =sdk-tools.d.ts= readable
- =reference/openai-codex/codex-rs/protocol/src/protocol.rs= and =models.rs=

** Why

A real Codex session from 2026-04-14 (thread id =019d8f43-…=) exposed four
distinct rendering bugs that should have been caught by test fixtures: a
dropped =TurnContext= type, a missing =GuardianAssessment= display, silent
discard of =CollabAgentSpawnBegin= events, and incorrect handling of a
=ReasoningDelta= without a preceding =AgentReasoning=. None of these would
have survived a fixture integrity test. We have no real-tools fixture today.

Every time a new tool type lands upstream — =Monitor= appeared in v2.1.109 with
zero warning — we discover it via a user report, not a CI failure. This survey
closes that loop.

**** Monitor tool — verbatim description (v2.1.109)

The following is extracted from =cli.js= string literals and =sdk-tools.d.ts=:

#+BEGIN_SRC text
Start a background monitor that streams events from a long-running script.
Each stdout line is an event — you keep working and notifications arrive in
the chat. Events arrive on their own schedule and are not replies from the
user, even if one lands while you're waiting for the user to answer a
question. Monitor is for the streaming case: "tell me every time X happens."
For one-shot "wait until X is done," use Bash with run_in_background instead.
#+END_SRC

Input shape:
#+BEGIN_SRC typescript
{
  description: string,        // human-readable label
  command:     string,        // shell command to run
  timeout_ms?: number,        // optional total timeout
  persistent?: boolean,       // keep running after turn end
}
#+END_SRC

Output: a =tool_result= whose =content= is a stream of text events, one per
matching stdout line. The tool_result block does NOT conform to the standard
single-result assumption that every other tool holds. This will break ccx's
current tool_result rendering path.

**** Top-level =RolloutItem= variants

Defined at =protocol.rs:2783=:

| Variant      | Description                                                         | ccx handled |
|--------------+---------------------------------------------------------------------+-------------|
| SessionMeta  | Immutable session header; emitted once at thread start              | Y           |
| EventMsg     | Event within a turn; 54 variants (see below)                        | partial     |

Rollout format version detection: rollouts containing =TurnContext= lines are
v2. Rollouts with only =SessionMeta= + =EventMsg= + =ResponseItem= are v1. ccx
handles =turn_context= deserialization today but does not record a version
discriminant or expose the version to the UI.

**** =SessionMeta= vs =TurnContext= relationship

=SessionMeta= is emitted once per rollout file, as the first line. It is
immutable for the lifetime of a thread.

=TurnContext= is emitted after each real user turn AND after mid-turn
compaction. It carries the execution baseline that a resume would need to
reconstruct the runtime state.

currently ignores all four.

**** Generic unknown-tool renderer

Add a thin adapter between =renderToolInput='s dispatch switch and the raw JSON
fallback:

#+BEGIN_SRC go
// UnknownToolRenderer is the structured fallback for tools with no
// specialised renderer. It renders a labelled key-value list rather than
// a raw JSON blob. The caller should use renderKnownTool first and fall
// through here only on no-match.
func renderUnknownTool(b *strings.Builder, name string, input map[string]any) {
    b.WriteString(`<details class="tool-unknown">`)
    b.WriteString(fmt.Sprintf(`<summary class="tool-unknown-name">%s</summary>`, html.EscapeString(name)))
    b.WriteString(`<dl class="tool-unknown-fields">`)
    keys := sortedKeys(input)
    for _, k := range keys {
        v := input[k]
        b.WriteString(fmt.Sprintf(`<dt>%s</dt>`, html.EscapeString(k)))
        vStr := renderFieldValue(v)
        b.WriteString(fmt.Sprintf(`<dd><pre>%s</pre></dd>`, html.EscapeString(vStr)))
    }
    b.WriteString(`</dl></details>`)
}
#+END_SRC

Key properties of this pattern:
- Never silent drop: every tool call produces visible output.
- Structured, not raw JSON: field names are labelled; values are pre-formatted.
- Collapsible: =<details>= hides verbose input by default.
- Namespace awareness: renderer peeks at =name= to annotate MCP tools
  (=mcp__*=), dynamic tools (from =SessionMeta.dynamic_tools= registry), and
  deprecated tools (=LocalShellCall=, =REPL=) with appropriate badges.

The existing switch in =renderToolInput= becomes the first dispatch tier; the
generic renderer becomes the second tier. The raw JSON fallback at line 1368
is removed entirely.

*** Post-run checklist

After running each prompt, before committing the fixture:

1. Locate the new rollout file:
   - CC: =~/.claude/projects/-tmp-ccx-fixture-cc/<uuid>.jsonl=
   - Codex: =~/.codex/sessions/2026/04/15/rollout-*-019d<...>.jsonl=
2. Run =ccx view <file>= against it to confirm ccx parses it without error.
3. Count element coverage:
   =awk -F'"type":' '{print $2}' <file> | cut -d, -f1 | sort | uniq -c=
   (Codex) or
   =jq -r '.type' <file> | sort | uniq -c= (CC, line-delimited JSON)
   Cross-check against the expected-coverage tables above.
4. Strip absolute paths that leak the dev machine. Replace with
   =/tmp/ccx-fixture/{cc,cx}= and the session UUIDs with stable
   =fixture-0001-...= IDs so the file is stable across regenerations.
5. Drop any line whose =payload= contains secrets (env vars, API keys,
   cookies). Monitor fixtures specifically: a rolling Bash output can carry
   environment fragments.
6. Save under =internal/provider/testdata/= with the fixture name and
   reference from =fixture_integrity_test.go=.

If you regenerate the fixture against a newer CLI version, BUMP the
filename (=fixture_claude_2_1_110_full_tools.jsonl=) rather than
overwriting — the old fixture still has value as a regression test for
older CLI versions.
