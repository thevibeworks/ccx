# ccx 2026-Q3 Goal Contract

A goal is a contract, not a wish. This file is the standing contract
for ccx work from 2026-07-15 until the four milestones below ship or
are explicitly re-decided. Each phase has its own DONE WHEN; an agent
picking up any phase should be judged against that phase's contract
without asking what we meant.

Decision record behind this contract:
`docs/devlog/2026-07-15-next-milestones.org`.

## Mission

ccx is the trusted, read-only viewer and auditor for agent CLI
sessions. Q3 outcome: ccx reads three providers (Claude Code, Codex,
Grok) with equal fidelity, presents them through one coherent
product shell, and the public repo proves it — so that when we do
the community launch, the proof matches the story.

## Global boundaries (frozen for every phase)

These override anything a phase contract says.

- **Read-only trust boundary.** ccx never writes to `~/.claude`,
  `~/.codex`, or `~/.grok` session data. Fork writes new files only;
  originals are never modified. Any change that would require write
  access to provider homes is out of contract — stop and ask.
- **Commit privacy gate.** No real session transcripts, session IDs,
  usage costs, home-directory paths, or internal identifiers in
  committed files. Fixtures are sanitized by construction. If a
  devlog or test needs real evidence, stop and get explicit approval
  for that exact material.
- **No skills/binary drift.** The bundled skills (`skills/ccx`,
  `ccx-recap`, `ccx-retro`) are embedded in the binary. Any CLI
  surface change lands in the same commit as its SKILL.md, README,
  and CHANGELOG updates. `v0.8.0` claimed to kill this class;
  reintroducing it is a contract violation, not a nit.
- **Docs claim only what the binary does.** README/SKILL.md features
  must be executable in the shipped binary (the JSON-export claim
  failed this test).
- **Sequencing.** Phase 0 gates everything: no feature work ships
  before v0.9.0 is tagged from a green repo — the gate is not
  housekeeping, it is the act of shipping the two finished feature
  sets. Phases 1 and 2 may overlap in design but land serially.
  Phase 4 (runner bridge) comes before the launch so the launch
  tells the complete story: three providers, one shell, runnable
  skills. Anti-drift guard: if the bridge stalls for more than two
  weeks past Kiln landing, launch without it — "one more feature"
  is how launches die.

## Phase 0 — v0.9.0 release gate

**Problem:** Two finished feature sets (turn evidence + deep links;
human-shape export + prompt sorting) sit unreleased behind five
verified blockers. Until they ship, the worktree is a growing merge
hazard and main is red.

**Outcome:** v0.9.0 tagged from a green repo, containing both
feature sets, with docs, skills, and CHANGELOG telling the truth.

**Scope:**
- In: the five blockers, three release commits, tag, release notes.
- Out: any new feature, any redesign work, any Grok code.
- Frozen: existing CLI flags and JSON schemas (`ccx.outline.v1`,
  `ccx.turn.v1`, `ccx.trace.v2`).

**The five blockers:**
1. Error-count source of truth: trace analysis counts errors from
   `tool_result` (`internal/trace/analysis.go:302`) while the web
   evidence panel scans `tool_use` mutations for `IsError`
   (`internal/web/templates.go:907`). Decide the single source of
   truth (default expectation: `tool_result` is truth — it is what
   the analyzer and cost rollups already use), fix the other side,
   and rewrite `internal/web/turn_evidence_test.go` to assert
   against real analyzer output, not a fabricated state.
2. Lint: fix unchecked `w.Write` in `internal/web/server.go:1696`,
   make the tag-triggered release workflow run the same lint as CI,
   and pin the linter version in `.github/workflows/ci.yml` (no
   `latest`).
3. Drift: SKILL.md documents `--shape human` and current `--sort`;
   README/CHANGELOG cover the staged web features; the false JSON
   CLI-export claim is removed or the format is implemented
   (default: remove the claim — implementing is Phase 3 material at
   the earliest).
4. Export permalinks: standalone HTML export must not emit `?turn=N`
   links that only resolve through the server. Either render
   self-contained anchors in the export or strip the links there.
5. Privacy: scrub or get explicit approval for the corpus
   measurements and internal identifiers in the 2026-07-13 devlog
   and the field-session figures in the staged devlogs, before any
   of them are committed.

**Contract:**
- DONE WHEN: `git tag v0.9.0` exists on main; CI is green on that
  commit including lint; the three commits are
  (a) docs/devlog after privacy scrub,
  (b) feat(web) turn evidence + deep links,
  (c) feat(export) human shape + prompt sorting;
  a downloaded HTML export contains no dead `?turn=` hyperlinks;
  the evidence panel's error count equals the trace outline's error
  count for the same turn on a real fixture session.
- VERIFY: `make test` (race included), `make lint`, `go build ./...`,
  fixture smoke tests for both providers, `ccx skills install` then
  diff installed SKILL.md against `ccx --help` surfaces, open one
  exported HTML file from disk and click every turn link, run the
  release workflow's lint step locally or in a dry-run branch.
- STOP RULES: stop if fixing blocker 1 reveals the analyzer itself
  is wrong (that becomes its own decided fix, not a drive-by); stop
  if splitting the worktree into the three commits requires
  discarding any hunk you cannot attribute to one of the two
  feature sets.
- PAUSE IF: privacy approval for the devlogs is needed (human
  decision); GitHub release credentials are unavailable.
- ITERATION: one blocker at a time, full test suite after each; max
  3 rounds on any single blocker before reporting what's stuck.

## Phase 1 — Grok provider parity

**Problem:** Grok Build stores sessions under `~/.grok/sessions/`
(prompts, tool calls, file snapshots) and ccx cannot read them. Our
core promise is provider parity; two of three major agent CLIs is
not parity.

**Outcome:** `ccx sessions|view|export|search|trace` work on Grok
sessions with the same fidelity as Codex support: discovery, parse,
terminal view, HTML/MD/Org export, and trace outline all produce
correct output on fixture sessions. Provider filter `--provider gx`
(final flag name decided in the spike) works everywhere `cc|cx` does.

**Scope:**
- In: new provider package under `internal/` mirroring the codex
  provider's structure; sanitized fixtures under `testdata/`;
  provider registration in catalog, web UI provider filter, config
  (`providers.grok`), doctor check, docs and bundled skills.
- Out: Grok cost estimation (hard exclusion until exact usage
  evidence exists in real session files — pricing guesses are a
  contract violation); resume/fork write-path for Grok; agent stdio
  integration (that is Phase 4).
- Frozen: existing cc/cx parsing behavior and all published JSON
  schema kinds; new provider must extend, never fork, the trace
  model.

**Sequencing inside the phase — discovery gates build:**
1. *Contract spike (discovery goal).* Read real local Grok sessions
   and the official docs (https://docs.x.ai/build/features/sessions,
   https://docs.x.ai/build/cli/reference). Deliverable: a session
   format reference in `docs/` (same genre as
   `2026-04-02-session-format-reference.org`) plus 3+ sanitized
   fixtures covering plain chat, tool calls, and file snapshots.
   Record the Grok CLI version the fixtures came from — the format
   is young and will churn.
2. *Build.* Parser, discovery, view/export/search/trace, web filter,
   doctor, docs — against fixtures only.

**Contract:**
- DONE WHEN: the format reference doc exists; fixtures are committed
  and sanitized; `ccx doctor` reports Grok home status; all five
  verbs produce correct output on the fixtures (golden-file
  assertions); `ccx trace` renders a Grok session outline with
  turns/steps/tool counts and explicitly omits cost; bundled skills
  and README document Grok support in the same commit.
- VERIFY: `make test && make lint`; fixture smoke test for Grok
  matching the cc/cx pattern; `ccx sessions --provider <grok-flag>`
  against a fixture home; schema audit (`make audit-schema`) passes
  with the new provider.
- STOP RULES: stop if Grok's format cannot map onto the existing
  turn/step trace model without schema changes (schema evolution is
  a separate decided change); stop if any fixture cannot be fully
  sanitized (do not commit "mostly clean").
- PAUSE IF: no real Grok sessions are available locally to build
  fixtures from (need a human to generate them); docs contradict
  observed format (surface the conflict, prefer observed format).
- ITERATION: spike is one pass then report; build lands verb by verb
  (discovery -> parse -> view -> export -> trace), tests green after
  each.

## Phase 2 — Kiln redesign

**Problem:** The web UI grew feature-by-feature into three competing
navigation rails, excessive bordered surfaces, weak hierarchy,
mobile navigation that disappears, and box-shadow animation with no
reduced-motion handling (`internal/web/static/style.css:2687`). It
reads as an accumulation, not a product.

**Outcome:** One product shell built around the audit workflow
`Observe -> Inspect -> Verify -> Export`: a single primary
navigation model, neutral working surfaces with terracotta as the
only identity accent, provider/state colors reserved for semantics
(provider badges, error/success states), motion mechanical and
sparse with `prefers-reduced-motion` respected, and a mobile
layout where navigation exists.

**Scope:**
- In: `internal/web/static/style.css`, `internal/web/templates.go`
  layout/markup, navigation structure, color tokens, motion.
- Out: server routes and handlers (markup may change, endpoints may
  not); a SPA rewrite — the server-rendered architecture decided in
  `docs/devlog/2026-06-17-spa-frontend-decision.org` stands unless
  that decision is explicitly reopened.
- Frozen: keyboard navigation (j/k, /, gg/G, d), dark/light theme
  toggle, in-session search, all existing URLs and deep links
  (including `?turn=N`), export output.

**Contract:**
- DONE WHEN: one navigation rail remains (mobile included); a color
  token audit shows terracotta used only as accent and provider/
  state colors only semantically; every animation honors
  `prefers-reduced-motion`; all pre-redesign web tests pass
  unchanged or with updates that are markup-only; fresh screenshots
  in `screenshots/` show session list, trace view, and evidence
  panel in both themes on desktop and mobile widths.
- VERIFY: `make test`; manual keyboard-nav pass (every shortcut
  above); resize check at 375px width; toggle
  `prefers-reduced-motion` and confirm no animated box-shadow;
  click-through of old bookmarked URLs.
- STOP RULES: stop if the redesign wants a route or handler change
  (that is product-shell scope creep into the server); stop if any
  frozen keyboard behavior would change; stop before deleting any
  CSS whose consumer you cannot name.
- PAUSE IF: a design decision needs taste judgment with no clear
  winner (present 2-3 options with screenshots, wait for a pick).
- ITERATION: kiln audit first (produce the critique + token plan as
  an artifact), then rebuild surface by surface (shell/nav, list
  pages, session view, evidence panel), screenshots after each; max
  2 refinement rounds per surface.

## Phase 3 — Burnish, two passes

**Pass 1: repository hygiene (start alongside Phase 0; it shares the
CI work).**

- Outcome: a stranger's 30-second read of the repo matches reality.
- In: green CI badge and actual green main; pinned toolchain
  versions (Go, linter, goreleaser); README accurate to the binary
  (no phantom formats, current flags, current screenshots after
  Phase 2); GitHub topics + homepage set; `llms.txt` at repo root;
  issues #2 and #6 reconciled (fixed, closed-with-reason, or
  converted to tracked milestones).
- Out: any community-building apparatus — no Discord, no star
  charts, no roadmap theater at this scale.
- DONE WHEN: CI green on main; `git grep -i` for stale version
  strings and dead flags returns nothing; both stale issues have a
  substantive close or a milestone; llms.txt validates against the
  llms-txt skill's checker.
- VERIFY: fresh-clone build on a clean machine (`make build` from
  scratch); README quick-start followed literally, top to bottom.

**Pass 2: community launch (blocked on Phases 1, 2, and 4 — with
the anti-drift guard from the sequencing rule).**

- Outcome: launch posts/show-and-tell published when the product
  demonstrates three-provider parity, a redesigned shell, and
  runnable skills via the bridge — proof matching story.
- STOP RULE: do not launch early because a news hook appears; the
  hook is not the proof. Symmetrically, do not delay past the
  anti-drift guard because one more feature feels close.
- DONE WHEN: launch content published with fresh multi-provider
  screenshots; install path verified from the published
  instructions on a machine that never had ccx.

## Phase 4 — Runner bridge (after Kiln, before launch)

**Problem:** We want ccx skills to be runnable ("check my session,
recap it") without hand-driving a CLI, but an internal agent loop
would break ccx's read-only trust boundary and duplicate
permissions, sandboxing, streaming, resume, and subagent machinery
that Claude Code, Codex, and Grok already own.

**Outcome:** `ccx run <skill> --agent codex|claude|grok` invokes the
installed CLI (or Grok's stdio protocol) with the chosen bundled
skill, after showing a dry-run disclosure of exactly what will be
executed and with which permissions, and retains a session receipt
(which agent, which skill, when, pointing at the provider's own
session file).

**Scope:**
- In: the adapter command, per-agent invocation shims, dry-run
  output, receipt storage under `~/.local/share/ccx/`.
- Out: any owned agent loop, any permission system of our own, any
  session-writing. The bridge launches; the provider CLI owns the
  session.
- Frozen: read-only boundary — the receipt lives in ccx's data dir,
  never in provider homes.

**Contract:**
- DONE WHEN: `ccx run ccx-recap --agent claude --dry-run` prints the
  exact command, skill payload, and permission implications without
  executing; a real run produces a provider-native session that
  `ccx trace` can then read; a receipt exists linking run -> session.
- VERIFY: dry-run golden test per agent; end-to-end run against one
  real provider CLI in CI-skippable integration test; `ccx trace`
  on the produced session.
- STOP RULES: stop if any adapter needs ccx to manage permissions
  itself (that is the boundary the milestone exists to avoid); stop
  and re-decide against a native loop ONLY with a written list of
  concrete adapter failures — "it would be nicer" does not qualify.
- PAUSE IF: a provider CLI has no non-interactive invocation path.

## Pre-mortem (derived constraints already folded in above)

Likeliest failures, named so we recognize them mid-flight:

1. *Gate blocker 1 fixed backwards* — patching the UI to satisfy the
   fabricated test instead of deciding the source of truth. Guard:
   the DONE WHEN requires outline count == panel count on a real
   fixture, not a passing unit test.
2. *Grok parser built from docs, not reality* — the docs are new and
   the format churns. Guard: fixtures from real sessions gate the
   build; observed format beats documented format; CLI version
   recorded in the reference doc.
3. *Kiln becomes a repaint or a rewrite* — either cosmetic CSS
   fiddling or an SPA adventure. Guard: DONE WHEN is structural (one
   rail, token audit, reduced-motion), and the 2026-06-17
   architecture decision is frozen.
4. *Launch drift, both directions* — announcing at v0.9.0 because
   the repo finally looks clean, or never announcing because the
   next feature always feels close. Guard: pass 2 is hard-blocked
   on Phases 1, 2, and 4, but the two-week anti-drift guard forces
   a launch without the bridge if it stalls.
5. *Runner bridge grows a loop* — "just a small executor" is how the
   trust boundary dies. Guard: native loop requires a written
   adapter-failure list; permissions stay provider-owned.
6. *Privacy leak via evidence-rich docs* — devlogs and fixtures are
   the two channels real data escapes through. Guard: global commit
   gate; fixtures sanitized by construction; approval is per-item,
   never blanket.

## Goal conditions (for /goal, per phase)

- Phase 0: `v0.9.0 tagged on green main; make test && make lint pass; exported HTML has no dead ?turn= links; evidence-panel error count matches trace outline on a real fixture`
- Phase 1: `all five verbs (sessions/view/export/search/trace) produce golden-verified output on sanitized Grok fixtures; make test && make lint && make audit-schema pass; no cost figures rendered for Grok`
- Phase 2: `single nav rail on desktop and mobile; prefers-reduced-motion honored by every animation; all keyboard shortcuts unchanged; fresh screenshots in both themes committed`
- Phase 3.1: `CI green on main; README quick-start reproduces on a fresh clone; issues #2 and #6 closed or milestoned; llms.txt present and valid`
- Phase 4: `ccx run <skill> --agent X works with dry-run disclosure and a receipt, and the produced session is readable by ccx trace`
